# 路线图（Roadmap）

本文档记录任务提醒应用后续的扩展方向、重构计划与推进顺序，基于 v1.5.6 的代码现状整理。
每完成一项，在对应条目前把 `[ ]` 改为 `[x]`，并注明版本或 PR。

状态说明：`[x]` 已完成　`[~]` 部分完成　`[ ]` 未开始

## 推进顺序总览

| 阶段 | 主题 | 核心内容 | 状态 |
|---|---|---|---|
| v1.5.7 | 可靠性 | 错过提醒补发、提醒队列、巡检校准、清理与同步冲突、CI + 类型检查 | 已完成 |
| v1.6 | 提醒体验 | 每周多天/工作日、法定节假日与调休、稍后提醒多档、全局快捷键快速添加 | 未开始 |

## 一、可靠性隐患（v1.5.7）

| # | 问题 | 位置 | 方案 | 状态 |
|---|---|---|---|---|
| 1.1 | 错过的提醒被直接丢弃：启动时只调度未来的一次性提醒，关机或应用未运行期间到点的待办不会再弹出 | `scheduler.rs` `schedule_existing` | 启动后首次巡检补发回溯 7 天内未触发的提醒；弹窗标注“错过的提醒 · 原定 HH:mm” | [x] |
| 1.2 | 同时到点的提醒互相覆盖：只有一个弹窗和一个快照，后到的覆盖先到的，前一条记录永远停在“待处理” | `scheduler.rs`、`state.rs` | 新增 `notification_queue.rs`，弹窗逐条处理并显示 `1 / N`，支持“全部知道了”；同一提醒重复触发时原位替换 | [x] |
| 1.3 | 计时依赖单次 `tokio::sleep`，系统休眠唤醒、修改系统时间后可能提前或延后 | `scheduler.rs` | 每 30 秒巡检一次（`fire_due`）；触发逻辑加锁并按提醒记录判重，与计时器重复命中也不会重复弹出 | [x] |
| 1.4 | 定期清理直接物理删除已完成任务，远端仍有该行，同步合并后会“复活” | `db.rs` `cleanup_data`、`sync.rs` | 清理改为先写墓碑；墓碑按保留期物理删除（本地 7 天，开启同步 60 天）；同步合并后、上传前清理过期墓碑 | [x] |
| 1.5 | 同步状态用中文文案做判断（`"同步成功"`），改文案就会破坏脏数据判断 | `sync.rs` `is_success_status` | 改为枚举/状态码存库，文案只在前端映射 | [ ] |
| 1.6 | WebDAV 密码明文存在 SQLite | `db.rs` settings | 改存系统凭据库（`keyring` crate，Windows 凭据管理器） | [ ] |
| 1.7 | 已软删除的提醒记录永远不会物理删除 | `db.rs` `cleanup_data` | 纳入墓碑清理（与 1.4 一并完成） | [x] |
| 1.8 | 已有类型错误未被发现（`pnpm build` 不做类型检查），其中包括提醒弹窗“跟随系统”主题监听参数错误 | 前端 | `pnpm build` 先执行 `vue-tsc --noEmit`，并修复存量错误 | [x] |

### 已知限制（有意为之）
- 一次性提醒只补发 **7 天内** 错过的（`MISSED_REMINDER_LOOKBACK_DAYS`），避免长期未使用后一次弹出大量陈旧提醒。
- 开启同步后，若某台设备超过 **60 天** 未同步，它上面已被其他设备删除的数据仍可能被重新上传。要彻底解决需要引入设备级同步水位，列入 2.x。

## 二、功能扩展

### A. 提醒能力（v1.6，投入产出比最高）
- [ ] **每周多天与工作日模式**：`WEEKLY` 目前只支持一个 `schedule_weekday`，改为位掩码（周一 = bit0 … 周日 = bit6），并提供“工作日”预设。需要新增迁移、调整 `recurrence.rs` 与表单。
- [ ] **中国法定节假日与调休**：“工作日”提醒遇节假日跳过、调休日照常提醒。节假日数据内置为 JSON（按年更新），可在设置中开关。
- [ ] **稍后提醒多档**：弹窗提供 5 分钟 / 15 分钟 / 1 小时 / 明早 9 点，而不是单一固定分钟数。
- [ ] **提前提醒**：待办区分“截止时间”与“提醒时间”，支持提前 10 分钟、1 天等。
- [ ] **勿扰时段**：勿扰期间只写记录不弹窗，结束后汇总到提醒队列（可复用 1.2 的队列）。
- [ ] **系统原生通知兜底**：`tauri-plugin-notification`，在全屏或游戏时也能看到。
- [ ] **弹窗内直接“完成”**：一次性待办的提醒弹窗增加“完成”按钮。

### B. 录入效率
- [ ] **全局快捷键快速添加**：`tauri-plugin-global-shortcut`，例如 `Ctrl+Alt+N` 弹出小输入框，回车即可添加。
- [ ] **自然语言时间解析**：识别“明天下午3点 交周报”“每周五 17:30 写周报”，先用规则 + 正则覆盖常见中文表达。
- [ ] **托盘显示下一条提醒**，托盘菜单可直接完成或推迟。

### C. 组织与视图（v1.7 / v2.0）
- [ ] **“今天”视图 / 时间线**：合并今日的一次性提醒与循环提醒，按时间排列。
- [ ] **统计面板**：基于 `reminder_records`（关闭 / 推迟 / 完成）展示完成率、推迟最多的任务、习惯打卡连续天数。
- [ ] **回收站**：软删除已具备，补一个恢复界面即可（注意墓碑保留期）。
- [ ] **标签 / 项目分组与优先级**，列表支持筛选排序；拖拽排序需新增 `sort_order` 字段。
- [ ] **日历视图**（月 / 周）。

### D. 便签
- [ ] 便签颜色和主题。
- [ ] 便签管理列表，一键显示或隐藏全部便签（配快捷键）。
- [ ] 贴边吸附。
- [ ] 便签内 Markdown 勾选框与任务完成状态联动。

### E. 数据与同步（v2.0）
- [ ] **导入导出**：JSON 全量备份、Markdown 导出待办、ICS 导出到系统日历。
- [ ] **本地自动备份**：每天 `VACUUM INTO` 一份，保留最近 7 份。同步合并出错时可用于恢复。
- [ ] **同步增强**：同步部分设置（主题、稍后提醒分钟数等）、端到端加密后再上传、坚果云等常见服务预设。

## 三、重构与工程化

### 前端
- [ ] **拆分 `App.vue`（约 2100 行）**：按 Tab 拆为 `TasksView.vue` / `CompletedView.vue` / `RecurringView.vue` / `RecordsView.vue` / `SettingsModal.vue`；数据逻辑抽到 `src/composables/`（`useTasks.ts`、`useRecurring.ts`、`useSync.ts`）；新建和编辑循环提醒合并为一个 `RecurringForm` 组件。**v1.7 做视图前先完成。**
- [x] **类型检查进入构建**：`pnpm build` = `vue-tsc --noEmit && vite build`，另有 `pnpm typecheck`。
- [ ] **引入 Vitest**：优先覆盖 `markdown.ts`、时间格式化等纯函数。

### 后端
- [ ] **拆分 `main.rs`（约 1300 行）**：命令拆到 `commands/{tasks,recurring,sticky,settings,notification}.rs`，窗口管理拆到 `windows/sticky.rs`。
- [ ] **状态字段强类型化**：`status`、`task_type`、`repeat_mode`、`action` 从 `String` 改为带 serde 的枚举。

- [x] **GitHub Actions**（`.github/workflows/ci.yml`）：Ubuntu + Windows 执行 `pnpm build`（含类型检查）、`cargo fmt --check`、`cargo clippy`（暂不阻断）、`cargo test`。
